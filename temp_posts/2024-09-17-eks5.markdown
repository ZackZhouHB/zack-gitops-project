Step 1: Installation and Basic Setup
Set up a Kubernetes cluster using AWS EKS.
Configure IAM roles for service accounts.
Install Karpenter using Helm or a YAML manifest.


Define and deploy a NodePool using Provisioner.
Test node provisioning by deploying a simple workload (e.g., Nginx).


Step 2: Scaling and Resource Management
Scaling Application
Ensures understanding of auto-scaling mechanisms based on workload demands.
Limit Resources
Configures resource limits and requests for applications.

Hands-On Steps:
Deploy a scaling application (e.g., a horizontal pod autoscaler).

Step 3: Disruption and Drift Management
Disruption: Focuses on maintaining application availability during scaling or updates.
Drift: Ensures nodes are reconciled with the desired state.

Hands-On Steps:
Configure Pod Disruption Budgets (PDBs).
Simulate disruption scenarios (e.g., delete a node).
Observe Karpenter's ability to recover workloads.

Step 4: Cost Optimization
Consolidation
Optimizes resource usage by consolidating workloads onto fewer nodes.
Using Spot Instances
Leverages AWS spot instances for cost reduction.
On-Demand & Spot Ratio Split
Balances cost efficiency and availability.

Hands-On Steps:
Deploy a Provisioner with spot instance configuration.
Create a workload that triggers the use of both on-demand and spot instances.
Test consolidation by simulating reduced workloads.

Step 5: Scheduling Constraints
Node Affinity, Taints and Tolerations, Topology Spread, Pod Affinity
Improves workload placement and resource utilization.

Hands-On Steps:
Configure nodeAffinity and taints in the workload YAML.
Define topology spread constraints to ensure even distribution.
Observe the impact of scheduling constraints on node provisioning.

Step 6: Observability
Observability
Ensures visibility into cluster and node behavior.
Hands-On Steps:

root@zackz:/mnt/f/1# eksctl create cluster -f - <<EOF
---
apiVersion: eksctl.io/v1alpha5
kind: ClusterConfig
metadata:
  name: ${CLUSTER_NAME}
  region: ${AWS_DEFAULT_REGION}
  version: "${K8S_VERSION}"
  tags:
    karpenter.sh/discovery: ${CLUSTER_NAME}

iam:
  withOIDC: true
  podIdentityAssociations:
  - namespace: "${KARPENTER_NAMESPACE}"
    serviceAccountName: karpenter
    roleName: ${CLUSTER_NAME}-karpenter
    permissionPolicyARNs:
    - arn:${AWS_PARTITION}:iam::${AWS_ACCOUNT_ID}:policy/KarpenterControllerPolicy-${CLUSTER_NAME}

iamIdentityMappings:
- arn: "arn:${AWS_PARTITION}:iam::${AWS_ACCOUNT_ID}:role/KarpenterNodeRole-${CLUSTER_NAME}"
  username: system:node:{{EC2PrivateDNSName}}
  groups:
  - system:bootstrappers
  - system:nodes
  ## If you intend to run Windows workloads, the kube-proxy group should be specified.
  # For more information, see https://github.com/aws/karpenter/issues/5099.
  # - eks:kube-proxy-windows

managedNodeGroups:
- instanceType: m5.large
  amiFamily: AmazonLinux2
  name: ${CLUSTER_NAME}-ng
  desiredCapacity: 2
  minSize: 1
  maxSize: 10

EOF

export CLUSTER_ENDPOINT="$(aws eks describe-cluster --name "${CLUSTER_NAME}" --query "cluster.endpoint" --output text)"
export KARPENTER_IAM_ROLE_ARN="arn:${AWS_PARTITION}:iam::${AWS_ACCOUNT_ID}:role/${CLUSTER_NAME}-karpenter"

echo "${CLUSTER_ENDPOINT} ${KARPENTER_IAM_ROLE_ARN}"
